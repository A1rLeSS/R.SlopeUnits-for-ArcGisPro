# 安装到成果导出审计与更新机制评估

日期：2026-11-14  
审计对象：R.slopeunits for ArcGIS Pro，`main` @ `5b78e25`，Release `v0.5.0`  
范围：安装器 → ArcGIS Pro Add-in → Python Toolbox/GRASS → 质量报告 → 成果导出

## 1. 结论摘要

插件已经形成完整闭环：安装器自带 GRASS、Add-in 解压 Tools、Python Toolbox 生成斜坡单元、质量报告输出 HTML/JSON/CSV/PNG，支持 GPKG/GDB。

当前最需要优先解决的不是再增加算法参数，而是：

1. **版本与 Release 对齐**，为自动更新打基础；
2. **批处理/参数扫描的真实端到端验证**；
3. **全分辨率 DEM 性能与可取消性**；
4. **成果导出/制图能力**；
5. **安装器签名与更新安全**。

自动更新评估结论：

| 能力 | 可行性 | 结论 |
|---|---|---|
| 在插件内检查 GitHub Release | 高 | 可实现 |
| 弹出双语更新日志 | 高 | 可实现，复用现有 WebView2 |
| 在插件内下载安装器 | 高 | 可实现，但安装器约 448 MB |
| 在插件内直接完成安装 | 中低 | Pro 运行时 Add-in/Tools/GRASS 可能被锁定；需要退出 Pro，由辅助更新器接管 |
| 完全静默自动安装 | 低（当前条件） | 需代码签名、版本化安装包、回滚和明确的用户确认 |

建议分两阶段：先做“检查 + 更新日志 + 下载”，再做“关闭 Pro 后辅助安装 + 重启”。

## 2. 安装器审计

### P0

1. **Release 标签与安装器源码不一致**  
   `v0.5.0` 标签仍指向 `cd87cf5`，而双语安装器源码在 `fe17163` / `5b78e25`。安装器资产已替换，但版本号仍是 0.5.0。  
   后果：如果现在实现更新检查，客户端会认为“已是最新”，无法发现双语安装器。  
   建议：下一次更新必须提升 `VERSION`、Add-in 版本、Installer 版本、Release 标签，并写入 Release notes。

2. **安装器未代码签名**  
   SmartScreen 可能拦截，自动更新下载并执行未签名 exe 的风险不可接受。  
   建议：自动安装前至少完成 Authenticode；否则只提供“打开 Release 页面/下载”。

### P1

3. **Pro 打开时直接覆盖 Add-in/Tools 可能失败**  
   安装器会写入 `Documents\ArcGIS\AddIns` 和 `%LOCALAPPDATA%\BasinSlopeTools`；Pro、Python、GRASS 可能锁定文件。  
   建议：更新器必须提示保存并关闭 Pro，等待进程退出后再运行安装器。

4. **卸载时未检查 GRASS/Python 进程**  
   卸载文档已提示关闭分析，但卸载器本身没有进程检查，可能留下不完整目录。

5. **Python Toolbox 首次信任提示**  
   首次使用必须允许第三方 Python 代码；目前无法通过普通安装完全消除。

6. **非 ASCII 路径覆盖不完整**  
   DEM 和输出路径已桥接；`grass85.bat`、`run_inside_grass.py`、`%TEMP%` 仍可能在中文用户目录下出问题。

7. **安装器体积约 448 MB**  
   更新下载成本高；没有增量更新或组件化更新。

## 3. 使用阶段审计

### P0

1. **批量生成/参数扫描缺少真实多 DEM 端到端验证**  
   代码支持断点续跑和汇总，但没有用多幅真实 DEM 验证失败恢复、文件占用和汇总一致性。

2. **全分辨率 7,895 × 7,895 DEM 没有完整基准**  
   只验证了 ADF 识别、中文路径导入和小范围流程；全量耗时、内存、临时空间未知。

### P1

3. **批处理/扫描只有进度，没有取消/暂停/重试队列**  
   ArcGIS Pro 的取消通常终止 Python 调用，GRASS 子进程清理依赖引擎异常处理，缺少产品级任务队列。

4. **没有拓扑/重叠/缝隙检查**  
   当前有形状紧凑度和狭长比例，但不检查单元重叠、缝隙、覆盖完整性和自相交。

5. **没有自动小单元合并/狭长单元后处理**  
   `r.slopeunits.clean` 之后仍可能出现碎片，需要可选合并策略。

6. **并发写入没有锁**  
   两个 Pro 实例同时运行可能竞争 `quality_reports.json`、批量状态和输出 GPKG/GDB。

7. **输出覆盖策略不够明确**  
   GPKG/GDB 已存在时由 GRASS/ArcPy 处理，缺少显式“覆盖/重命名/中止”选择。

8. **Pro 3.0–3.6 未逐一验证**  
   目标框架是 3.0，但只在 3.7 实机验证。

## 4. 成果导出审计

已支持：

```text
GPKG
GDB
HTML 质量报告（含预览 PNG）
JSON 质量报告
CSV 质量报告
run_manifest.json
```

不足：

1. 没有 Shapefile、GeoJSON、DXF、CSV 属性表等常用交换格式；
2. 没有地图版面/PDF/打印输出；
3. 预览图不是制图产品，没有比例尺、指北针、图例、坐标网；
4. 没有成果包（GPKG + 报告 + 预览 + manifest）一键打包；
5. 没有“导出前检查输出字段/坐标系/空几何”的验收步骤；
6. 质量评分仍是相对启发式，缺少人工判读校准。

## 5. 值得新增的功能

### 第一优先级

5. **成果一键打包**：GPKG/GDB + HTML/JSON/CSV + PNG + manifest；
6. **Shapefile / GeoJSON / CSV 属性导出**。

### 第二优先级

8. **分块/并行处理全分辨率 DEM**；
9. **参数自动寻优**：目标单元数/面积/CVAR/耗时；
10. **UI 双语**：目前安装器双语，插件界面仍以中文为主；
11. **安装/更新日志与回滚**；
12. **质量评分人工校准**。

### 研究型

13. **流域约束斜坡单元**：禁止跨流域、流域边缘处理；
14. **不确定性/可复现性包**；
15. **多 DEM 泛化验证**。

## 6. 自动更新实现方案

### 6.1 触发方式

当前 `Module1` 是 `autoLoad="false"`，不会在 Pro 启动时自动加载。可选：

- **A. 插件首次使用时检查**（推荐）：点击任一 R.slopeunits 按钮时，异步检查一次；不阻塞工具。
- **B. Pro 启动检查**：将 `autoLoad` 改为 `true`，在 `Module.Initialize`/`OnApplicationReady` 中异步检查；会增加启动负担。
- **C. 独立“检查更新”按钮**：最可控，适合首版。

建议先用 A + C，稳定后再考虑 B。

### 6.2 检查逻辑

```text
GET https://api.github.com/repos/A1rLeSS/R.SlopeUnits-for-ArcGisPro/releases/latest
```

- 只接受非 draft、非 prerelease；
- 读取 `tag_name`、`body`、`assets`；
- 比较语义版本（当前 Add-in 版本必须从统一常量读取）；
- 使用 `ETag`/`If-None-Match` 和 24 小时缓存，避免 GitHub API 60 次/小时限制；
- 超时 5–8 秒，失败静默，不阻塞 Pro。

### 6.3 更新日志弹窗

复用现有 WebView2：

- 显示版本号、发布日期、双语 Release notes；
- 按钮：`稍后`、`下载更新`、`打开 GitHub`；
- 下载前显示文件大小（约 448 MB）和 SHA256 校验说明。

### 6.4 下载

- 下载到 `%LOCALAPPDATA%\BasinSlopeTools\updates\`；
- 使用 `HttpClient` 流式下载，显示进度/取消；
- 下载 `SHA256SUMS.txt`，校验安装器 SHA256；
- 校验失败删除文件并提示。

### 6.5 安装

**不能可靠地在 Pro 运行期间覆盖已加载的 Add-in。**

可行流程：

1. 用户点击“下载并安装”；
2. 提示保存工程并关闭 ArcGIS Pro；
3. 启动独立 `Updater.exe`（或 PowerShell 辅助脚本），它不依赖 Pro；
4. 等待 Pro 进程退出；
5. 运行安装器：

```text
BasinSlopeTools_Setup_0.5.exe --silent --accept-license
```

6. 安装完成后可选重启 Pro；
7. 失败时保留旧安装并显示日志。

更保守的方案：

- 只下载并打开安装器，由用户手动关闭 Pro 后安装；
- 或只打开 GitHub Release 页面。

### 6.6 安全条件

自动安装前必须具备：

- GitHub HTTPS；
- Release 资产 SHA256 校验；
- 最好有 Authenticode 代码签名；
- 只允许固定仓库/固定资产名；
- 不允许运行 Release notes 中的任意链接；
- 用户明确确认，不强制关闭 Pro；
- 失败回滚/保留旧版本。

### 6.7 版本前提

当前状态不满足自动更新：

```text
Release 标签：v0.5.0 -> cd87cf5
安装器源码：fe17163 / 5b78e25
VERSION：0.5.0
```

安装器已更新但版本号未变，更新器无法识别。下一次发布必须：

1. 提升 `VERSION`、Add-in 版本、Installer 文件版本；
2. 打新 tag（如 `v0.5.1`）；
3. 重新生成安装器/便携包/文档/SHA；
4. 用新版本测试“旧版 → 新版”升级。

### 6.8 结论

- **检查更新 + 双语更新日志**：可实现，工作量约 2–3 天；
- **插件内下载**：可实现；
- **插件内直接安装**：不能保证在 Pro 运行时完成，必须退出 Pro 并由辅助更新器接管；属于“程序内发起、程序外完成”；
- **完全静默自动安装**：当前不建议，需签名、版本化和回滚机制。

## 8. v0.6.0 实施状态

已在 v0.6.0 实现：

- 插件内更新中心：检查 GitHub Release、双语日志、下载、SHA256 校验、延迟安装器；
- 版本集中管理：`AddinInfo.Version`、`VERSION`、DAML、Installer、Tools revision；
- 一键 ZIP 成果包；
- Shapefile / GeoJSON / CSV 属性导出；
- 几何有效性 + 重叠面积比例；
- 质量历史、批处理状态文件跨进程锁；
- 显式覆盖开关；
- 安装/卸载前检查 GRASS/Python 分析进程。

仍受外部条件阻塞、未在 v0.6.0 完成：

- 代码签名（没有可用证书）；
- Pro 3.0–3.6 每个版本实机验证（本机只有 3.7）；
- 7,895 × 7,895 全量基准（耗时/资源超出本轮）；
- 分块/并行、参数自动寻优、PDF 地图版面；
- 完整重叠/缝隙/自相交修复（当前为检测，不自动修复）；
- 批任务真正暂停/取消（ArcGIS Pro 工具取消会终止 Python，产品级队列未实现）；
- 插件 UI 全双语（更新窗口为中文，安装器双语）；
- 质量评分人工校准。

因此“自动更新”属于**可用但需真实发布/签名/重启验证**的状态；直接静默安装在无签名和 Pro 锁定条件下仍不建议开启。
